# 쟁점 문서 글쓰기 원칙

이 문서는 세법 쟁점 학습문장을 처음부터 쓰고 검수하는 편집 기준이다. 목적은 AI 탐지 회피가 아니라, 독자가 사실과 법리를 따라갈 수 있는 문장을 만드는 데 있다.

현재 집필·검수의 상위 기준은 [세무쟁점 학습노트 범용 설계](superpowers/specs/2026-09-06-general-tax-learning-note-design.md)이다. 기존 원고나 사이트가 없어도 적용하며 문장·질문·사례·판례 개수는 제한하지 않는다. 실제 제작 범위는 별도 실행계획에서 정한다.

## 기본 규칙

- 사례형 노트는 사실관계 전문을 먼저 제시한 뒤 독자가 무엇을 판단할지 질문으로 분명히 쓴다. 사례가 불필요한 개념 노트는 개념이 필요한 상황에서 출발한다.
- 문장의 관계를 자연스럽게 이어 쓴다. 한 사실 문단을 문장별 카드로 분할하지 않는다. 필요한 날짜·금액·당사자·문서명을 구체적으로 적는다.
- 금액은 `50,000원`처럼 표시하고 거래 규모와 단위를 확인한다. 학습용 사례의 개인은 역할을 붙인 갑·을·병, 법인은 업종에 맞는 가상 상호로 적는다. 실제 판례의 사실과 금액은 임의로 바꾸지 않는다.
- 주어와 동사를 앞에 둔다. “검토가 이루어졌다”보다 “세무서가 경정했다”처럼 쓴다.
- 법률용어는 바꾸지 않되, 처음 나올 때 짧은 우리말을 붙인다.
- 결론을 여러 번 다시 말하지 않는다. 한 단계의 답은 그 단계에서 끝낸다.
- 자료가 없으면 “확인되지 않음”이라고 쓴다. 빈칸을 추정으로 채우지 않는다.
- 가상 사실은 학습용 사실이라고 표시한다. 실제 사건처럼 꾸미지 않는다.

## 줄일 표현

다음 표현이 문장에 정보를 더하지 않으면 삭제하거나 구체적인 말로 바꾼다.

- 종합적으로 살펴보면, 핵심적으로, 다음과 같이, 이와 관련하여
- 매우 중요한, 종합적인, 체계적인, 다양한, 획기적인
- 결론적으로, 다시 말해, 쉽게 말하면을 반복하는 구조
- “이 사례가 보여 주는 것은…”처럼 중요성을 선언하는 문장

## 쟁점 단계의 문장 순서

사실관계 전문 다음에는 질문 하나와 그 답·해설을 함께 제공한다. 기본 흐름은 다음과 같으며, 모든 항목을 별도의 목차로 강제하지 않는다.

```text
직관적인 질문 → 직접적인 답과 사실·법령 적용 해설 → 필요한 증빙·판례·실무 효과
```

사건 전체 사실은 처음에 한 번 쓰고 질문에서는 필요한 대상을 짧게 짚는다. 조문은 설명 가까이에 연결하고 원문에 접근할 수 있게 둔다. 조건 변경이 필요하면 바뀐 사실을 해당 질문 직전에 명시한다. 사례 추가나 조건 변경 자체를 강제하지 않는다. 독립 개념 설명에는 억지 사례를 만들지 않는다.

질문은 독자가 실제로 결정할 일을 묻는다. 답을 의문문으로 변환하거나 ‘자료는 어느 부분을 입증하는가?’를 반복하지 않는다. 각 해설은 해당 질문에 맞게 작성하며 공통 설명 문장을 순환 배치하지 않는다. 자료 확인을 지시하는 데 그치지 않고 확인 결과가 판단에 미치는 영향을 설명한다.

## 판례 문장

판례는 필요한 깊이로 설명하며 문장 수를 고정하지 않는다. 다음 내용이 독자에게 전달되어야 한다.

1. 법원이 본 쟁점
2. 결론과 그 결론을 만든 사실
3. 현재 쟁점에서 사용할 수 있는 범위와 사용할 수 없는 범위

판결문에서 확인하지 않은 판시나 사건 사실은 쓰지 않는다. 사건번호만 나열하지 않는다.

법원·선고일·사건번호와 공식 출처를 확인하고 사건 당시 법령과 현재 법령의 차이를 검토한다. 여러 판례가 서로 다른 경계나 예외를 설명하면 필요한 만큼 추가한다. 확인되지 않은 자료로 개수를 채우지 않는다.

## 검토 체크리스트

- [ ] 사례형 노트에서는 사실관계 전문이 질문보다 먼저 보이는가?
- [ ] 각 질문이 사실 범위·행위·법적 판단을 명시하는가?
- [ ] 관련 조문이 그 질문에 필요한가?
- [ ] 답이 방금 주어진 사실만으로 설명되는가?
- [ ] 같은 사례나 문장이 다른 단계에 반복되지 않는가?
- [ ] 날짜·금액·출처가 확인되는가?
- [ ] 판례의 범위를 과장하지 않았는가?
