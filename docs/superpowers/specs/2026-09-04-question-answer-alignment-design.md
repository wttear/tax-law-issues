# 질문·답 정렬형 세법 쟁점 리더 설계

## 배경과 문제 정의

현재 `question_blocks`의 질문은 핵심 질문·회상 문항·조문 템플릿을 순서대로 모아 만들고, 답은 전문가 판단·쉬운 설명·법령 요약을 별도로 순환 배치한다. 따라서 질문이 여러 판단을 한꺼번에 묻는데 답은 그중 한 단계만 답하거나, 질문은 자료를 묻는데 답은 계산을 제시하는 불일치가 생긴다. 질문을 읽어도 답이 무엇을 해결하는지 예측하기 어려운 것이 핵심 문제다.

## 목표

- 한 질문이 하나의 판단·계산·증빙 확인만 묻게 한다.
- 질문과 답을 같은 판단 단위에서 함께 생성해 주제와 사실·금액을 맞춘다.
- 전체 사실관계 전문은 문서 앞에 한 번만 두고, 질문은 그 사실에서 주체·행위·기준·결과를 명시한다.
- 답은 질문의 핵심 명사와 숫자를 받아 직접 결론부터 말한다.
- 질문·답·조문·증빙·판례 연결이 서로 다른 주제를 가리키지 않도록 자동 검증한다.

## 독자에게 보이는 읽기 계약

각 쟁점은 다음 순서를 유지한다.

1. 사실관계 전문
2. 쟁점의 핵심 질문
3. 질문별 판단 블록
4. 판례·조사·회계 연결
5. 조건이 달라지는 경우와 마지막 정리

각 판단 블록은 `질문 → 판단할 사실 범위 → 관련 조문 → 답과 해설 → 해당 증빙·판례·회계` 순서다. 질문은 시험 지시문이나 저자용 안내가 아니라, 사실관계에 대한 직접적인 판단문으로 쓴다.

## 판단 단위와 질문 유형

원고에서 추출한 법리·사실·금액·증빙·효과를 하나의 `judgment_unit`으로 묶는다. 한 쟁점에서 우선 다음 유형을 순서대로 채운다.

| 유형 | 질문이 묻는 것 | 답의 형태 |
|---|---|---|
| 요건 판정 | 특정 거래·행위가 법정 요건을 충족하는지 | 해당 여부와 결정적 사실·조문 |
| 사실 적용·계산 | 주어진 금액·비율·기간을 적용한 결과 | 식 또는 날짜와 세무상 금액 |
| 증빙·신고 연결 | 결론을 입증할 원본과 신고 반영 위치 | 자료명과 확인할 사실 |
| 조건 변경 | 한 조건이 바뀔 때 결과가 어떻게 이동하는지 | 바뀐 결론과 영향 범위 |

모든 유형을 기계적으로 채우지 않는다. 원고에 근거가 없는 유형은 생략하고, 최소 두 개의 서로 다른 판단 단위만 남긴다.

질문은 다음 형식을 따른다.

`[주체/거래]가 [법적 기준 또는 계산 기준]에 따라 [하나의 결과]인가/얼마인가/어떤 자료로 확인되는가?`

증빙 단위는 자료 목록과 입증 대상을 바로 매칭하는
`[핵심 자료] 등 자료는 사실관계의 어느 부분을 입증하는가?` 형식을 우선한다.
계산 단위는 `계산식을 계산하면 [결과 항목]은 얼마인가?`, 조건 변경 단위는
`[바뀐 조건]이면 결론은 어떻게 달라지는가?`처럼 결과를 질문 안에 명시한다.

`어떤 순서로 설명할까요`, `무엇을 고를까요`, `어떻게 연결할 것인가`처럼 답의 범위가 열려 있는 메타 질문과 쉼표로 네 가지 이상을 나열하는 복합 질문은 사용하지 않는다.

## 생성 데이터 계약

기존 `case_facts`는 유지한다. `question_blocks`는 다음 필드를 가진다.

```json
{
  "block_no": 1,
  "judgment_type": "calculation",
  "question": "행정벌 3,000과 감가상각 한도초과 6,000을 가산한 세무조정 금액은 얼마인가?",
  "fact_scope": "행정벌·감가상각비의 장부 반영액과 세법상 조정액",
  "legal_refs": ["법인세법 제19조", "법인세법 제23조"],
  "article_ids": ["..."],
  "answer": "두 금액 합계 9,000을 익금산입·손금불산입으로 가산한다.",
  "explanation": "행정벌과 상각초과액은 장부비용에 이미 포함되어 있으므로 세전이익에서 다시 차감하지 않고 조정명세서에 가산한다.",
  "evidence": ["비용원장", "감가상각비조정명세서"],
  "precedent_refs": [],
  "accounting_note": null
}
```

`judgment_type`은 질문과 답의 의도를 검증하는 내부 데이터이며 화면에는 간단한 유형 라벨만 필요할 때 사용한다. 기존의 `new_fact`·`next_state`는 추가하지 않는다.

## 생성 알고리즘

1. 사실관계와 원고 섹션을 정규화한다.
2. 전문가 판단·쉬운 설명·세무조정의 문장을 근거·요건·계산·효과 단위로 분리한다.
3. 각 단위에서 주체, 대상, 숫자·날짜, 법적 동사, 결론을 추출한다.
4. 추출된 결론을 먼저 확정하고, 그 결론을 묻는 짧은 질문을 같은 단위에서 만든다.
5. 질문 유형별 템플릿은 단위를 명확히 만들 때만 사용하며, 질문 후보를 독립적으로 모은 뒤 답에 순서대로 붙이지 않는다.
6. 질문·답에 공유되는 핵심 토큰(주체, 거래, 금액, 날짜, 법적 용어)을 확인하고, 공유 토큰이 부족하면 해당 단위를 버리거나 중립적인 재작성 템플릿으로 보완한다.
7. 동일한 답·질문·증빙이 반복되면 하나로 합치고, 조문 번호만 답으로 남는 블록은 허용하지 않는다.

## 문장 원칙

- 질문 하나에 판단 동사 하나를 둔다: `해당하는가`, `얼마인가`, `무엇으로 확인하는가`, `어떻게 바뀌는가`.
- 질문은 사실관계에 나온 주체·금액·기간을 가능한 한 그대로 쓴다.
- 답은 첫 문장에서 결론·금액·효과를 말하고, 둘째 문장에서 이유를 보충한다.
- 질문의 숫자·주체·대상이 답에 없으면 질문을 다시 쓴다.
- “전체적으로”, “순서대로”, “어떻게 설명” 등 범위를 흐리는 연결어를 줄인다.
- 법률명·조문·판례의 정확성을 우선하고, 불확실한 결론은 조건부로 표시한다.

## 검증

- 50개 쟁점 모두 두 개 이상의 판단 블록을 가진다.
- 각 질문은 물음표 하나로 끝나고, 복합 나열·메타 지시형 패턴이 없다.
- 질문과 답 사이에 주체·대상·숫자·법적 핵심어가 정규화된 형태로 두 개 이상 공유된다.
- 계산형 질문은 답에 숫자 또는 계산 결과가 있고, 요건형 질문은 해당 여부와 이유가 있다.
- 증빙형 질문은 답 또는 증빙 목록에 자료명이 있고, 조건 변경형 질문은 바뀐 조건과 결론을 함께 가진다.
- 답이 조문 번호만이거나 질문의 핵심어를 전혀 포함하지 않으면 빌드를 실패시킨다.
- 사실관계 전문이 질문 블록보다 먼저 렌더되고, 질문 블록 내부 순서가 유지된다.

## 범위 밖

- 법령 원문·판례 색인의 내용 자체를 새로 조사하거나 재작성하지 않는다.
- 50개 쟁점의 범위와 모바일 레이아웃을 바꾸지 않는다.
- 질문 이해도를 높이기 위해 원고에 없는 새로운 법률 결론을 추정하지 않는다.
